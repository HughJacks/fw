# fw — design notes (the technical map)

fw is a terminal free-writing app growing, deliberately slowly, into a
personal knowledge manager built on blocks and live quotes. This file is
the technical map: principles, files, the data model, the architecture,
and working on it. Every key is in `KEYS.md`.

## Principles

Slow and without bloat; standard library only; functional code: a block is a recursive option type,
pure functions, I/O at the edges; one user, one machine; undo is total;
everything is a block.

## Data model (schema v15)

The store is `{schemaVersion: 15, blocks: [Block]}`: everything is a block.
Blocks are flat (side by side, by id) and content is recursive.

```
Block   = { id, title, entry?, created, updated, words, content, links?, paraphrases?, visits? }
Content = Text    "a string"
        | Blocks  ["<id>", …]                         children, in order
        | Quote   {"quote": "<id>", "mask"?, "show"?: [prop…], "inner"?: {"<quote id>": mask}}
        | Image   {"image": "<hash>.<png|jpg|gif|webp>"}    a file in images/
links   = [{to: entry id, at: [start, end], created?}]  spans of a text block's text
paraphrases = "<id>"                                    on any block but a quote
mask (on disk) = {block id: [[start, end], …]}          what shows of each block of the target
visits  = {total, first, recent: [[minute, flags], …]}   the last 10 visits; minutes since the epoch; flags of o c w q
```

- **Entry**: a top-level block, marked `"entry": true`; a child has no
  mark (its parent lists it; the tree is stored once, downward). Entries
  are the roots `collect` keeps alive.
- **Ids** `YYYYMMDDThhmmss-xxxx`. **Titles** written or null (derived on
  display). **`words`** counts what a block shows, quotes flattened, each
  block once. **`updated`** is stamped by `save_data` (`stamp_updated`),
  up to the entry, not through quotes.
- **`visits`** (v15, readOnly): stretches of attention, each ending after
  10 minutes without any (`VISIT_GAP`). Flags: `o` the pericope opened,
  `c` the cursor stayed 3 s (`VISIT_DWELL`) or typed, `w` written in, `q`
  through a quote. Carried up like `updated` (the block, its containers, its
  entry; not through quotes). Never an edit: not in `updated`, words,
  `content_hash`, undo (`restore` keeps them); two copies merge as a union
  (`merge_visits`). The editor notes them (`Editor.visit_tick`, state in
  `fw_state.Visits`, pure steps `attend`/`note_visits`/`ended` in
  `fw_block`) and writes them with `record_visits` when a visit ends, on
  leaving a pericope and on quit. `fw_block.visits(b)` reads them;
  `$FW_CLOCK` sets the time in tests.
- **Pointers, not objects:** a quote *is* the edge (its mask lives on it);
  a link and a paraphrase mark are attributes; none keeps anything alive.
  **Backlinks** are derived (`fw_block.backlinks`), never stored.
- **Masks:** per block on disk; in memory anchors into the target's draft,
  in open/close pairs (`masks_in` / `masks_out` in `fw_block` convert on
  read and write). `inner` masks narrow the quotes inside (intersection).
- **Deleting is unlinking:** `collect()` erases blocks no entry reaches
  through children or quotes (or the clipboard holds, `clip_holds`).
- **Migrations** (`fw_migrate.py`, pure, one step per version) run as
  `load_data` reads the store; `migrate` saves the result. A schema change
  adds a step.
- Code takes blocks apart with `match`: `children`, `quoted`, `image_of`,
  `paraphrases`, `links`, `own_text`, `block_items`, `full_text`,
  `block_draft`.

### The draft (what the editor edits)

`block_draft` renders a block's children as plain lines: each text child
after a hidden `{{block <id>}}` marker line, each quote as `{{quote
<target> <quote-block-id>}}`, each picture as `{{image <id>}}`; a
container's children name the containers they're in, innermost first, to
any depth (`{{block <id> <container> <its container>…}}`). `parse_draft`
(with `parse_nest`) and `format_draft` are inverses; `draft_items` →
`set_content` (via `write_content`, which carries links along) writes one
back. Blank lines at a block's edges are trimmed and empty blocks dropped,
except marked ones (`keep`).

### Writes

- **One transaction shape:** `transact(change)` locks, loads, applies the
  change, collects, recounts words, validates, saves. `StoreError` on
  refusal. (`commit` isn't on it yet.)
- **Commands on it:** `commit_view`, `set_quote_mask(s)`, `mask_quote_to`,
  `set_quote_show`, `detach`, `pop_out`, `nest_out`, `new_entry`,
  `link_text`, `add_links`, `unlink_text`, `set_paraphrase`,
  `new_paraphrase`, `delete_entry`, `let_go`, `restore`.
- **Undo records:** store-side actions return `{blocks: {id: copy | None}}`;
  `restore(record)` applies one and returns its inverse (undo and redo).
- **Sessions:** `stage` writes the draft and its `.meta.json` sidecar
  (header fields, pid, `base` hash, `synced` digest), next to the code; `commit` refuses a save over a change
  made elsewhere; `finish` skips a draft already saved. The editor saves
  as the keys stop and re-reads the store 4 times a second (`POLL_MS`).
- **Writing from a script:** never by hand-editing the JSON; go through
  these same functions.

## Architecture of the editor

- **The buffer** is `lines` plus `bids` (one block id per line, None on a
  quote or image line) plus `nest` (child → container); `tidy_bids` and
  `fold` keep them consistent after every key.
- **Modes** are records in `fw_state.py`; keys go to `Editor.key_<mode>`.
  State a mode owns is a field of its record.
- **Edit-through quotes:** `stack` holds the blocks open below the current
  one, each frame with its own `lines`, `bids`, undo and view mode; a
  masked quote's buffer is its view (`vmode`), saved through the lens
  (`commit_view`).
- **Undo entries** are `(lines, bids, cy, cx, extra)`; `extra` holds the
  mode, copies of the quote blocks in the buffer, and an optional store
  record.
- **Layout and drawing** live in `fw_layout.py` (`box_plan`, rows as
  named tuples, the one text column past `MAX_DEPTH` boxes); pictures go
  up after curses draws (`fw_image`).
- **Menus** are `Command`s in `fw_menu.commands` (close or stay, top level
  or submenu); keys are data in `fw_keys.py`
  (`decode` → key name, `bind(name, context)` → action; contexts text,
  mask, header, picker).
- **Masking** (`fw_mask_ui.py`) works on one stream over the quote and the
  quotes inside (`build_flow`), with set operations from `fw_lens` and the
  result split per block (`split_mask`).

## Working on it

- **Develop on a copy**, run `tests/run.sh`, check no session is open
  (`pgrep -fl "fw_app|fw_edit"`),
  install, then `python3 fw_store.py migrate`. **Never swap code under an
  open session** (the zsh `fw` script included).
- **Tests:** `tests/run.sh [suite…]`, each suite in a temp copy, one per
  core (about 10 s). Shared helpers in `tests/fwtest.py` (throwaway store,
  fw or the editor in a pty read with pyte, `$FW_SYNC` waits instead of
  sleeps). The suites need `pyte` in `tests/.venv` (`run.sh` says how);
  `FW_TEST_JOBS=1` runs them one at a time.
