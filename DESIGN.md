# fw — design notes (the technical map)

fw is a terminal free-writing app growing, deliberately slowly, into a
personal knowledge manager built on blocks and live quotes. This file is
the technical map: principles, files, the data model, the architecture,
and working on it. Every key is in `KEYS.md`.

## Principles

Slow and without bloat; standard library only, except the store's `loro`
(in `.venv`); functional code: a block is a recursive option type, pure
functions, I/O at the edges; one user, whose copies of the store on
several machines merge; undo is total; everything is a block.

## Data model (schema v17)

The store is `{schemaVersion: 17, blocks: [Block]}`: everything is a block.
Blocks are flat (side by side, by id) and content is recursive. That's the
data fw works on; on disk it's a Loro document (`fw_loro`, since
2026-11-16), so copies on several machines merge by themselves
(`fw_store.py merge FILE` takes another copy's `.loro` in; `merge_file`
tidies a merge the same way everywhere).
`load_data`/`save_data` are unchanged.

```
Block   = { id, title, entry?, created, updated, words, content, links?, paraphrases?, kinds?, visits? }
Content = Text    "a string"
        | Blocks  ["<id>", …]                         children, in order
        | Quote   {"quote": "<id>", "mask"?, "show"?: [prop…], "inner"?: {"<quote id>": mask}, "lock"?: true}
        | Image   {"image": "<hash>.<png|jpg|gif|webp>"}    a file in images/
        | Kind    {"kind": "<name>", "blocks": ["<id>", …]}  what a block can be: its description, children
links   = [{to: entry id, at: [start, end], created?}]  spans of a text block's text
paraphrases = "<id>"                                    on any block but a quote
kinds   = {"<kind id>": true | false}                   what it is (or isn't): only your answers
mask (on disk) = {block id: [[start, end], …]}          what shows of each block of the target
visits  = {total, first, recent: [[minute, flags], …]}   the last 10 visits; minutes since the epoch; flags of o c w q
```

- **Entry**: a top-level block, marked `"entry": true`; a child has no
  mark (its parent lists it; the tree is stored once, downward). Entries
  are the roots `collect` keeps alive.
- **Ids** `YYYYMMDDThhmmss-xxxx`. **Titles** written or null (derived on
  display). **`words`** counts what a block shows, quotes flattened, each
  block once. **`updated`** is stamped by `save_data` (`stamp_updated`),
  up to the entry, not through quotes.
- **`visits`** (v15, readOnly): stretches of attention, each ending after
  10 minutes without any (`VISIT_GAP`). Flags: `o` the pericope opened,
  `c` the cursor stayed 3 s (`VISIT_DWELL`) or typed, `w` written in, `q`
  through a quote. Carried up like `updated` (the block, its containers, its
  entry; not through quotes). Never an edit: not in `updated`, words,
  `content_hash` or undo (`restore` keeps them); a merge takes the union
  (the minutes a map, the total a counter: `fw_loro`). The editor notes them (`Editor.visit_tick`, state in
  `fw_state.Visits`, pure steps `attend`/`note_visits`/`ended` in
  `fw_block`) and writes them with `record_visits` when a visit ends, on
  leaving a pericope and on quit. `fw_block.visits(b)` reads them;
  `$FW_CLOCK` sets the time in tests.
- **Kinds** (v16): a kind (a poem, a to-do) is a block whose content is
  Kind, a name and a description made of ordinary child blocks, always an
  entry; `children`, `own_text`, `block_items`, `block_draft` treat it as a
  container, and `with_children` writes one back keeping its name. A block
  says what it is in `kinds`, only your answers (several allowed).
  A model's guesses are never stored: a model outside fw may write
  `kind-guesses.json` beside the store; `store.load_guesses`
  reads it (again when it changes; none or broken: {}), and the pure
  `fw_block.guessed` keeps those that count (unanswered, both `updated`
  still as guessed, p ≥ `GUESS_AT` 0.9, kinds that exist); they meet the
  answers in `merge_kinds` (answers win; `of_kind` takes guesses).
  Shown dim blue on the kinds line, "poem?" (`Editor.guesses`, `Ink.blue_guess`):
  Enter confirms one (a yes), Backspace or Delete denies it (a no), each
  through `store.set_kind`, one undo step; Ctrl+O opens the kind.
  A kind learned from the answers (`fw_block.learned`: kind-guesses.json's
  `sources`, "learned" once it has 10) has its guesses that count applied,
  and so does any kind about a block inside a pericope (`fw_block.is_applied`):
  drawn like a yes with a mark, "note·", listed undimmed in its search
  (`Picker.applied`), still never stored.
  A kind's header has a derived maybes line (`fw_block.maybes`: its guesses
  about pericopes from `MAYBE_AT` 0.5 up, a learned kind's only under 0.9, likeliest first;
  and how many are applied); Enter there begins a review
  (`Editor.start_review`, a `fw_state.Review`): fw_app opens each maybe in
  turn (`next_maybe`), its editor in mode
  "review" (`key_review`, keys context "review": Enter yes, Backspace no,
  Tab skip, ^Z back, ^Q stop; nothing types), then the kind again, each
  answer one undo step there (`Editor.reviewed`).
  Kinds a model proposes: a model outside fw may write
  `kind-proposals.json` beside the store (a form of writing shared by 5+
  pericopes no kind covers). Home
  (the garden) offers one as a dim card after "+ new pericope" (`fw_picker.PROPOSE`;
  `fw_block.open_proposals` with `kind_cover`): Enter makes the kind
  (`store.kind_from_proposal`: the drafted sentence and live quotes of
  typical members as its description) and reviews its members
  (`write(("propose", p))`, a `Review` with no p); ^D dismisses it
  (`ask_dismiss`, `store.dismiss_proposal`, kept in `kind-dismissed.json`
  beside the store).
  Set from the header's kinds line, a token per answer (`Editor.kind_chips`,
  keys in the "kinds" context: `kinds_key`): the kinds picker (`open_kinds`,
  a Menu stage "kinds") adds one, yes or no, or makes a new kind
  ("+ new kind"), and Backspace on a token takes one back, each one undo
  step (`store.set_kind`, `answer_kind`); Enter or Ctrl+O on an answer's token opens the kind.
  Said as text: "poem, not letter" (`set_kinds`, `parse_kinds`).
  The store applies them apart from the header's other fields
  (`APPLIED_APART`). A kind's name is its title (`display_title`), renamed
  from its header's title field as you leave it (`store.rename_kind`,
  `Editor.apply_field`; refused empty or another kind's, case aside); all
  that shows it reads it from the kind. Not an edit
  (`updated` ignores it); deleting a kind drops answers about it; Turn into
  a quote moves them with what the block held. Backlinks of a kind are the
  blocks of that kind. Searching a kind's name puts the kind and its blocks
  first, then the blocks guessed to be one, dim (`Picker.kind_first`); a kind's row is its name, drawn blue (`Ink.blue`, `blue_soft`,
  `blue_tag`; `kind_boxes` in the layout). A merge keeps `kinds` answer by
  answer (each its own key in the document: `fw_loro`), never a conflict.
- **Types**: every header's top line says what the open block is made of,
  derived, never stored: `fw_block.block_type` (text, image, kind, quote,
  block) and `type_label` ("kind: poem").
- **Locks** (v17): `lock: true` on a quote keeps anyone writing through
  it, and through everything shown through it, at any depth; it's the
  quote's, not its source's. One pure function decides:
  `fw_block.locked_by(blocks, path)`, over the quotes open from the
  pericope inward (`Editor.open_quotes`): the outermost locked one, else
  None. The editor asks it before every write (`Editor.refuse` in
  `key_text` and `key_blocks`, `Commands.lock_refuses` for menu commands
  and their keys, a dropped picture, `/`); a quote's own mask, top line and
  lock are its holder's, refused only when the path to it is locked
  (`Editor.quote_locked`). A locked buffer has its own undo history
  (`history_key`), so no earlier text step is undone through it. Drawn: `⊘`
  first on its top line, what shows through it dim. Toggled from Ctrl+/ or
  Ctrl+L (`toggle_lock`, `store.set_quote_lock`).
- **Pointers, not objects:** a quote *is* the edge (its mask lives on it);
  a link and a paraphrase mark are attributes; none keeps anything alive.
  **Backlinks** are derived (`fw_block.backlinks`), never stored.
- **Masks:** per block on disk; in memory anchors into the target's draft,
  in open/close pairs (`masks_in` / `masks_out` in `fw_block` convert on
  read and write). `inner` masks narrow the quotes inside (intersection).
- **Deleting is unlinking:** `collect()` erases blocks no entry reaches
  through children or quotes (or the clipboard holds, `clip_holds`).
- **Migrations** (`fw_migrate.py`, pure, one step per version) run as
  `load_data` reads the store; `migrate` saves the result. A schema change
  adds a step.
- Code takes blocks apart with `match`: `children`, `quoted`, `image_of`,
  `kind_of`, `paraphrases`, `kinds_of`, `links`, `own_text`, `block_items`,
  `full_text`, `block_draft`.

### The draft (what the editor edits)

`block_draft` renders a block's children as plain lines: each text child
after a hidden `{{block <id>}}` marker line, each quote as `{{quote
<target> <quote-block-id>}}`, each picture as `{{image <id>}}`; a
container's children name the containers they're in, innermost first, to
any depth (`{{block <id> <container> <its container>…}}`). A kind is
drafted as its description's children, like any container (it's always an
entry, so it's never a line in another block's draft: it's quoted there). `parse_draft`
(with `parse_nest`) and `format_draft` are inverses; `draft_items` →
`set_content` (via `write_content`, which carries links along) writes one
back. Blank lines at a block's edges are trimmed and empty blocks dropped,
except marked ones (`keep`).

### Writes

- **One transaction shape:** `transact(change)` locks, loads, applies the
  change, collects, recounts words, validates, saves. `StoreError` on
  refusal. (`commit` isn't on it yet: 'Left from the audit'.)
- **Commands on it:** `commit_view`, `set_quote_mask(s)`, `mask_quote_to`,
  `set_quote_show`, `set_quote_lock`, `detach`, `pop_out`, `nest_out`, `new_entry`,
  `link_text`, `add_links`, `unlink_text`, `set_paraphrase`,
  `new_paraphrase`, `set_kinds`, `set_kind`, `rename_kind`, `delete_entry`, `let_go`, `restore`.
- **Undo records:** store-side actions return `{blocks: {id: copy | None}}`;
  `restore(record)` applies one and returns its inverse (undo and redo).
- **Sessions:** `stage` writes the draft and its `.meta.json` sidecar
  (header fields, pid, `base` hash, `synced` digest), next to the code; `commit` refuses a save over a change
  made elsewhere; `finish` skips a draft already saved. The editor saves
  as the keys stop and re-reads the store 4 times a second (`POLL_MS`).
- **Writing from a script:** never by hand-editing the JSON; go through
  these same functions.

- **The garden** (home): `fw open`, and quitting the editor, land on a
  grid of cards, one per pericope (`fw_picker.Garden`, built in
  `fw_app.home_garden`): "+ new pericope" first, then the first `TOP`
  mixing the recent (active in the last `RECENT_DAYS`) and the resurfacing
  (dropped out of memory) in turn, then the rest of each, then the others by
  last activity (`fw_block.garden`). Ctrl+G shows it as a list, a row each
  (`Garden.grid`, `draw_list`). Each card: title, made/changed, what last
  happened and when (`last_action`, `ago`), the start of its text. Memory is
  FSRS-style and derived from `visits`, never stored (`fw_block.memory`:
  stability replayed from the visits, each graded by its strongest flag,
  w > c > q > o; retrievability `(1 + t/9S)^-1`; under `FADED_AT` it
  resurfaces, the most rehearsed first, at most `RESURFACE`). Arrows move
  over the grid; typing hands over to the search (`Picker`), Backspace with
  nothing typed comes back. Home is kept as it was left between visits
  (`fw_state.Home`, owned by `fw_app.app`): after a delete or coming back,
  the same view, search and place.
- **Back and forward** (the breadcrumbs, no bar for them yet): Ctrl+[ steps
  back as ^Q does, and what's left is kept (`Home.forward`: entry and draft
  offset, `Editor.where`); Ctrl+] opens the last again where it was, from the
  editor (stepping in as Open it, `Editor.forward`) or home. Anything opened
  anew clears what's ahead (`fw_app.write`). Ctrl+[ is told from Esc by the
  kitty keyboard protocol.

## Architecture of the editor

- **The buffer** is `lines` plus `bids` (one block id per line, None on a
  quote or image line) plus `nest` (child → container); `tidy_bids` and
  `fold` keep them consistent after every key.
- **Modes** are records in `fw_state.py`; keys go to `Editor.key_<mode>`.
  State a mode owns is a field of its record.
- **Edit-through quotes:** `stack` holds the blocks open below the current
  one, each frame with its own `lines`, `bids`, undo and view mode; a
  masked quote's buffer is its view (`vmode`), saved through the lens
  (`commit_view`).
- **Undo entries** are `(lines, bids, cy, cx, extra)`; `extra` holds the
  mode, copies of the quote blocks in the buffer, and an optional store
  record.
- **Layout and drawing** live in `fw_layout.py` (`box_plan`, rows as
  named tuples, the one text column past `MAX_DEPTH` boxes); pictures go
  up after curses draws (`fw_image`).
- **Menus** are `Command`s in `fw_menu.commands` (close or stay, top level
  or submenu); keys are data in `fw_keys.py`
  (`decode` → key name, `bind(name, context)` → action; contexts text,
  mask, header, picker).
- **Masking** (`fw_mask_ui.py`) works on one stream over the quote and the
  quotes inside (`build_flow`), with set operations from `fw_lens` and the
  result split per block (`split_mask`).

## Working on it

- **Develop on a copy**, run `tests/run.sh`, check no session is open
  (`pgrep -fl "fw_app|fw_edit"`), back up your store,
  install, then `.venv/bin/python fw_store.py migrate`. **Never swap code under an
  open session** (the zsh `fw` script included).
- **Tests:** `tests/run.sh [suite…]`, each suite in a temp copy, one per
  core (about 10 s). Shared helpers in `tests/fwtest.py` (throwaway store,
  fw or the editor in a pty read with pyte, `$FW_SYNC` waits instead of
  sleeps). `tests/.venv` needs `pyte` and `loro`.
